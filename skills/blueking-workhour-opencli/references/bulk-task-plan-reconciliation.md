# 蓝鲸既有任务与新版排期表批量对齐

## 适用场景

用户给出新版排期截图/表格，并要求把蓝鲸中的“我的任务”按新版计划调整；尤其适用于任务合并、取消、整体前移、工时变化等批量改造。

## 已验证工作流

1. **先读取真实蓝鲸状态，不直接按截图写入**
   - 用 OpenCLI 打开任务表。
   - 通过任务列表 API 获取当前用户经办的任务，至少读取：`id`、任务编号、标题、状态、经办人、预计开始/结束日期、预估工时。
   - 不要仅依赖当前页面 20 条可见数据；使用 `size=100` 或分页读取。

2. **从截图形成目标基线**
   - 提取任务标题、工时、开始日期、结束日期。
   - 对疑似 OCR 标点错误（嵌套括号、全角/半角符号）保留语义正确的现有标题，不主动写入明显错别字；在方案中注明。

3. **按语义和排期逐项配对**
   - 不只按行号配对，优先使用标题语义、任务编号连续性、当前日期范围共同判断。
   - 输出“当前配置 → 目标配置 → 操作”的对照表。
   - 单独列出：保持不变、只改日期、改标题/日期/工时、合并后多余任务。

4. **任务合并采用复用 + 取消，默认不物理删除**
   - 选择与目标任务开始日期或语义最接近的既有任务进行复用。
   - 其余被合并掉的任务建议转为“取消”，并写明合并原因，保留操作轨迹。
   - 在实施前读取被取消任务的状态和已有工时；若已有工时记录，不直接取消，先向用户报告影响。

5. **先给改造方案，再实施**
   - 当用户说“先给改造方案，再去实施”时，本轮只能读取和规划，不做任何字段更新或状态流转。
   - 方案必须明确：任务编号、旧值、新值、操作类型、总工时变化、拟取消任务。
   - 等用户确认关键决策后再执行，例如“复用哪个任务”“多余任务是否取消”。

6. **实施顺序**
   - 先修改被复用/合并的任务。
   - 再处理多余任务的取消。
   - 然后按任务编号或时间顺序批量修改日期和工时。
   - 每次写入后回读；全部完成后再次读取整组任务，校验有效任务数、总工时、时间连续性、经办人和状态。

## 计划输出模板

| 蓝鲸任务 | 当前配置 | 目标配置 | 操作 |
|---|---|---|---|
| `任务编号` 标题 | 工时；开始～结束 | 新标题；新工时；新开始～结束 | 保持/修改/取消 |

最后必须列出：

- 当前有效任务数量与目标数量；
- 当前总工时、目标总工时及差值；
- 哪些任务会改标题、工时、日期或状态；
- 明确声明“当前尚未实施修改”。

## 会话案例（2026-07）

新版排期把两个 PDS 定时任务合并成一个“推进 JDE 评审 + 改造评估”。处理方案采用：

- 复用开始日期与目标一致的既有任务，修改标题、结束日期和工时；
- 另一条多余任务建议取消而非删除；
- 后续开发任务按截图整体前移；
- 单独识别某列表任务从 8h 增加到 16h；
- 用计算工具核对整组预估工时从 232h 调整为 200h，差值 -32h。

此案例说明：批量改造不能只平移日期，还要同时检查任务数量、合并关系和工时变化。
